# 图库批选 + 导入搬家 设计文档

> 2026-09-22。两部分：**① 图库多选 → 批量归档 / 批量删除**；
> **② 导入功能搬进图库 + 测量页下拉框按文件夹收窄**。
>
> 合成一份文档的原因：两块都在改图库顶栏那一片区域，分两次做会互相踩。

---

## 背景：现在的分工是乱的

| | 测量页 `/` | 图库 `/gallery` |
|---|---|---|
| 打开照片 | ✅ 下拉框 + 「打开」 | ✅ 点卡片 |
| **导入照片** | ✅ 按钮 / 拖拽 / Ctrl+V | ❌（空库时给个「去导入」跳到测量页） |
| **手机传图二维码** | ✅ 侧栏 | ❌ |
| 改名 / 删除单张 | ✅ | ❌ |
| **归档到文件夹** | ❌ | ✅ 卡片上的「归档…」 |
| 待确认导入列表 | ❌（跳去图库） | ✅ |

结果：**「照片从哪来」和「照片怎么管」全挤在测量页**，而「测量」本身是图库里点进来的。
下拉框更是完全不带上下文 —— 不管你从哪个文件夹点进来，它都列全部照片。

**做完之后**：图库 = 照片的家（进照片、管照片）；测量页 = 只负责量。

## 一、测量页的范围（scope）

### 1.1 范围怎么传

复用图库 `folder` 那一套语义，**一个字符串**：

| 值 | 含义 |
|---|---|
| 不带这个参数 | 全部照片 |
| `"0"` | 未分类 |
| `"3"` | 文件夹 id=3 |

图库卡片链接从 `/?id=12` 改成 **`/?id=12&folder=3`**（在「全部照片」页就是 `/?id=12`，不带参数）。

测量页启动时读它：

```js
const u = new URLSearchParams(location.search);
const f = u.get('folder');            // null = 没这个参数
S.scope = f === null ? '' : f;        // '' | '0' | '3'
```

### 1.2 范围要写回地址栏

[measure.html:1860](../../../web/measure.html#L1860) 现在写的是 `?id=${S.imageId}`，会把 `folder` 抹掉。
改成 `?id=N` + `&folder=X`（scope 非全部时才带）。**不这么做，刷新一次范围就没了** —— 违反「刷新保持现状」。

范围**不进 localStorage 的 session**，只活在地址栏里。理由：地址栏本来就会被 rewrite，刷新天然带得住；多存一份就多一个会不一致的地方。

### 1.3 下拉框按范围加载

`loadPhotos()` 从 `fetch('/api/images')` 改成带上 `folder` 参数。

**顶栏要多说一句话**，否则用户不知道下拉框为什么只有 12 张：

```
[图库] [实验A ▾] [打开]   当前范围：实验A（12 张）· 看全部
```

- 范围是「全部」时，这句话整个不显示（省得每次都说废话）
- 「看全部」= 把 `S.scope` 置空 + 重写地址栏 + 重载下拉框

**「看全部」是单向放宽，没有反向收窄的入口。** 收窄必须回图库点。理由：反向入口要么再加一个文件夹选择器（和左边那棵树重复），要么让用户在一堆文件夹里挑（图库已经在干这件事了）。

### 1.4 下拉框现在会静默丢照片

`GET /api/images` 默认 `limit=200`，而 `loadPhotos()` 不带任何参数 —— **第 201 张往后根本不在下拉框里，界面上一个字都不说。**

两处一起修：

1. `app/api/images.py` 的 `limit` 上限从 `le=500` 放宽到 `le=1000`，前端显式传 `limit=1000`
2. 前端发现 `total > items.length` 时，在 `<select>` 末尾加**一条禁用项**：
   `—— 还有 12 张没列出来，去图库挑 ——`

不静默截断是重点。1000 这个数字是拍的，但配了第 2 条之后，拍错也只是多一句提示，不会骗人。

> 性能：`_summary()` 每行查两次库（测量条数 + 所属文件夹）。1000 行 ≈ 2000 次 SQLite 查询，实测这个量级在百毫秒内，不优化。真慢了再说。

### 1.5 拖拽 / Ctrl+V 留在测量页

**按钮和二维码搬走，拖拽和粘贴留下。** 用户明确要保留这个便利。

| 情况 | 行为 |
|---|---|
| 当前**没有**打开照片 | 导入 → **自动打开**那张 |
| 当前**正开着**一张在量 | **只导入，不抢** —— 状态栏提示「导入 N 张，从上面的下拉框里选」 |
| 一次拖进来 ≥2 张 | 照旧：进待确认列表，跳 `/gallery?pending=1` |

「不抢」这条是**保留现有保护**（[measure.html:1894](../../../web/measure.html#L1894)）：自动打开会清空撤销链（`hist.past` / `hist.future`），正在量的那张的撤销就回不去了。用户已确认保留。

**拖拽永远导入到「未分类」**（新导入的照片本来就没有文件夹归属），**绝不进用户当前浏览的那个文件夹**。

**并且：自动打开时，范围强制切回「全部」。**
必须这么做 —— [measure.html:1855](../../../web/measure.html#L1855) 是 `$('picker').value = String(S.imageId)`，
如果新照片不在下拉框的选项里，`value` 会被**静默忽略**，下拉框显示的是一张别的照片。切回全部之后它一定在。状态栏同时说明：

```
已导入：IMG_0001（在「未分类」里，去图库可以改）
```

- **「手机传图」** —— 点开**弹窗**显示二维码。不塞进侧栏：侧栏是文件夹树，塞二维码是两码事

- 随之作废的 `refreshNet()` 和那个 `setInterval`（**删掉，不留死代码**）

拖拽 / 粘贴的监听（`dragenter` / `dragover` / `dragleave` / `drop` / `paste`）**保留** —— 不只是功能，更是拦截：不拦的话浏览器会直接导航到拖进来的文件，把正在量的东西全冲掉。

## 三、图库：多选模式

### 3.1 进入与退出

顶栏「选择」按钮 → 顶栏下面多出一条操作栏：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 图库  [搜名字…] [排序▾] [状态▾]  87 张   [导入照片] [手机传图] [选择]  回到测量页 │
├──────────────────────────────────────────────────────────────────────┤
│ 已选 3 张   [全选本页]                 [归档…] [删除] [退出]          │
└──────────────────────────────────────────────────────────────────────┘
```

（当前页 24 张全被勾上之后，`[全选本页]` 旁边才会长出 `[选中全部 87 张]` —— 规则见 3.2）

- 选择模式下**点卡片任意位置 = 勾上 / 取消**，不再跳去测量页
- 卡片上的「归档…」小按钮**藏起来**（`body.selmode .card .file { display: none }`）——
  留着它看着能点、其实整张卡片都在响应勾选，会误触
- 缩略图左上角出现勾选角标，选中时卡片描边
- **一张都没勾时 `[归档…]` 和 `[删除]` 禁用**（`disabled`）——
  不禁用的话点「删除」会弹出一个「删掉 0 张照片」的确认框
- 退出：点「退出」或按 `Esc`（弹窗开着时 `Esc` 仍然先关弹窗）

### 3.2 选择状态

```js
const SEL = { on: false, ids: new Set() };   // 具体 id，不做 all/except 三态
```

**「选中全部」是把 id 拉成一张具体清单**，不引入「全选」这个抽象状态。代价是快照：之后新导入的照片不在里面（可接受）。

- **「全选本页」** 一直显示，点它把当前页 24 张的 id 加进去
- **「选中全部 N 张」** 只在两件事同时成立时出现：① 当前页全被勾上 ② `S.total > SEL.ids.size`
  （这是用户选的 Gmail 那种做法：先勾当前页，再给你一个「全部」）
  点它 → `GET /api/images/ids?...` → 把返回的 id 全加进去

### 3.3 改筛选不清空已勾

**搜索词 / 排序 / 状态 / 文件夹 / 翻页 —— 都不清空已勾的。** 理由：先筛「未测量」再「选中全部 87 张」一次删掉，是这个功能的正当用法，清空就没法用了。

代价是换页后看不见勾（勾还在）。三重兜底：

1. 操作栏一直写着「已选 N 张」
2. 删除确认框里写的是**服务端算出来的真实张数**（见 3.5）
3. 已勾的照片在别处被删掉时，服务端会跳过它，确认框里那个数字跟着变小 —— **不会多删**

### 3.4 批量归档

```
把选中的 24 张放进文件夹
可以同时放进好几个文件夹；一张都不勾就是「未分类」。

  ⦿ 也放进这些文件夹 —— 它们原来在的文件夹都保留
  ○ 换成这些文件夹 —— 原来的一律取消

  ☑ 实验A      ☐ 实验B      ☐ 实验C
                                              [取消] [保存]
```

- 单选**默认「也放进」**（安全的那一边）
- 文件夹列表带缩进，复用 `TREE.items` 的 `depth`，和现有的 `askChecks` 画法一致
- 「换成」+ 一个都不勾 = 全部变「未分类」，提示语已经写了

复用 `ask(title, hint, content, buttons)`（[gallery.html:1213](../../../web/gallery.html#L1213)）——
它接受任意 DOM 当 content，所以单选 + 多选拼在一个 wrap 里就行，**不用改 `askPicker` / `askChecks`**。

### 3.5 批量删除

**删除要问两次，第一次是问服务端。**

1. 先 `POST /api/images/batch-delete {image_ids, dry_run: true}` → `{count, measured}`
2. 再弹确认框：

```
删掉 24 张照片
原图会挪进 data/trash/（不是真删，磁盘上还找得到）。
其中 3 张量过线，测量记录会一起没，不能恢复。
                                              [取消] [删掉这 24 张]
```

- `measured = 0` 时那句换成「测量记录会一起没，不能恢复。」
- 两个按钮都不用 `danger` 样式会被忽略 —— 用 `ask` 已有的 `danger` 支持
- 确认后 `POST /api/images/batch-delete {image_ids}`

**为什么要 dry_run**：不这么问，「其中 3 张量过线」这句话在跨页/全选的时候前端根本算不出来
（它手里只有当前页那 24 行的 `line_count`）。而且 dry_run 和真删走的是**同一个解析函数**，预览的数字和实际删的永远一致。

### 3.6 选择模式要扛住刷新

块 ⭐ 铁律：刷新保持现状。选择模式**和已勾的 id 一起存 localStorage**（`jltx.sel`），刷新后原样回来。

不入地址栏：URL 已经装了 `q` / `order` / `status` / `folder` / `page` 五个参数，再塞一串 id 会很难看，而且和已有的 `writeUrl()` 打架。

## 四、接口

### 4.1 新增（都在 `app/api/images.py`）

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /api/images/ids` | `status` `q` `folder`（和图库同一个筛选） | `{"ids": [...], "total": N}` |
| `POST /api/images/batch-delete` | `{"image_ids": [...], "dry_run": false}` | dry_run：`{"count": N, "measured": M}`<br>真删：`{"deleted": N, "moved_to_trash": M}` |
| `POST /api/images/batch-folders` | `{"image_ids": [...], "folder_ids": [...], "mode": "add"\|"replace"}` | `{"updated": N}` |

**行为约定**

- `image_ids` 空列表 → **400**（不是静默 no-op —— 前端不该发出这种请求）
- `image_ids` 里不存在的 id → **跳过，不报错**。照片可能在别处被删了，为这个让整批失败不值得
- `mode="add"`：每张的结果 = 原有 ∪ 新的；`mode="replace"`：每张的结果 = 新的（空列表 = 未分类）
- `folder_ids` 里任何一个文件夹不存在 → **400**（复用 `folders._require_folder`）
- 删除：原图走 `storage.trash_file()` 挪进 `data/trash/`，再 `db.delete_image()`（测量记录由外键级联删）

**`trash_file` 天然保护 `样品集/`** —— 它只动 `DATA_DIR` 底下的文件，老记录的照片留在原地，
返回值 `moved_to_trash` 会小于 `deleted`。前端提示语要照实说。

### 4.2 改动的

`GET /api/images` 的 `limit`：`Query(200, ge=1, le=500)` → `Query(200, ge=1, le=1000)`。

### 4.3 新增的 db 层函数（`app/db.py`）

```python
def ids_matching(conn, *, status="all", q="", folder=None) -> list[int]
def count_measured(conn, image_ids: list[int]) -> int      # 有测量记录的照片张数
```

`ids_matching` **复用现有的 `_filter()`**，和图库格子墙保证是同一套筛选条件。

### 4.4 不新增的

- 不新增 `GET /api/images/{id}` —— 已存在
- 不新增批量改名 —— 没这个需求
- 不改 `/api/folders/*` —— 批量归档走照片这一侧，和文件夹那侧独立

## 七、取舍与已知风险

1. **选择模式刷新后还在**（存了 localStorage）。好处是守住了「刷新保持现状」；
   代价是隔天回到图库时可能看到一堆勾还留着 —— 靠操作栏的「已选 N 张」和确认框兜底。
2. **「选中全部 N 张」是快照**，点完之后新导入的照片不在里面。
3. **已勾的照片在别处被删** → 服务端跳过，确认框里的真实张数会变小，**不会多删**。
4. **图库顶栏变挤**（6 个控件），窄屏会换行。没做折叠菜单。
5. **拖拽导入会改范围**：正开着「实验A」时拖一张新图进去（且当时没打开任何照片），
   范围会切回「全部」。这是必须的（见 1.5），但用户会觉得"我怎么跳出来了"——
   状态栏有说明。
6. **「看全部」是单向的**，没有反向收窄入口。
7. **下拉框上限 1000**。超了会给一条「还有 N 张没列出来」的禁用项，不静默截断。
8. **手机上能用但没为触屏优化**：选择模式下的小勾在手机上不好点。图库主要在电脑上看。
9. **选择模式下钩的是"照片"，不是"当前筛选结果"**。切筛选不会把已勾的踢出去 ——
   这是有意的，但意味着「我先筛窄再勾」和「我先勾再筛窄」的结果一样。
