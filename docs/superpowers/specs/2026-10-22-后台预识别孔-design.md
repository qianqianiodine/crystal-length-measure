# 后台预识别孔（起点圆缓存）— 设计文档

日期：2026-10-22
状态：用户已确认方向（"可以"）

## 1. 背景

打开一张还没标定过的照片时，服务端会跑 `detect.detect_wells()` 猜一个起点圆。
2026-10-22 实测（`样品集/` 5 张图）：

| 步骤 | 耗时 |
|---|---|
| `imageio.load_rgb()` 解码 | 0.00～0.03 秒 |
| `detect.detect_wells()` 检测 | **4.42～4.98 秒** |

用户一张一张打开，每张都要等约 5 秒。用户原话：

> 平时能不能后台自动识别我导入到文件夹的图片的孔（加入文件夹的图片是我肯定要看的）
> 但是每次单个单个识别都很慢

## 2. 目标

- 照片**加入文件夹**后，在后台提前算好起点圆。
- 打开这些照片时**直接用缓存**，不再等 5 秒。
- 不改变检测算法、不影响未进文件夹的照片。
- 打开一张还没轮到的照片时，仍然现场检测（5 秒），**绝不因为后台队列而卡住**。

## 3. 非目标

- 不做检测算法优化（不拿精度冒险）。
- 不把预识别写成正式标定（不写 `calibrations` 表）——否则图库缩略图会提前
  画出基于"未核对圆"的标尺，可能误导。
- 不加界面进度（用户没要求；以后需要可加）。
- 不预识别没进文件夹的照片。

## 4. 数据

`images` 表新增一列：

```sql
rough_circle TEXT   -- 起点圆 JSON：{"cx","cy","a","b","th","auto":true}
```

- 新库：写进 `SCHEMA`。
- 老库：加进 `MIGRATIONS`，启动时 `ALTER TABLE` 补列。
- 空 / 坏 JSON 一律当"没有缓存"，下次打开时现算。

不新建表：一图一份，跟着图走，删图自动没。

## 5. 后台线程（`app/bgdetect.py`）

- 一个 daemon 线程 + `queue.Queue`，**一次只算一张**（检测 5 秒，不抢满 CPU）。
- `enqueue(ids)`：去重后入队；**没启动时直接返回**（测试环境不跑后台）。
- `start()`：启动线程；只由 `app.launch` 设的 `JLTX_BG_DETECT=1` 触发。
- `enqueue_existing()`：启动时查一遍「在文件夹里、没缓存、没标定」的图，全部排队。
- `_process(iid)`：
  1. 图还在吗？
  2. 已有缓存？→ 跳过
  3. 已标定？→ 跳过
  4. 还在任何一个文件夹里吗？→ 不在就跳过
  5. 原图文件在吗？
  6. `circle_from_file()` → `images.rough_circle`
- 任何异常都吞掉、继续下一张 —— 一张坏图不能弄死后台线程。
- 后台线程用自己的 SQLite 连接（`db.get_conn()`），只在这个线程里用。

## 6. 打开图片时

`main.open_photo()` 里原来的 `_rough_circle()` 换成：

```python
c = bgdetect.cached_or_detect(conn, row, p, width, height)
```

- 有 `images.rough_circle` → 直接返回（**不调用检测**）。
- 没有 → 现算，并写回 `rough_circle`（下次就快了）。
- 算不出来 → 居中默认圆（和现在一样，保证界面上总有圆可拖）。

## 7. 触发点

照片进入任何一个文件夹时入队：

1. `PUT /api/images/{id}/folders`（单张归档）
2. `POST /api/images/batch-folders`（批量归档；`add` 和 `replace` 都算）
3. `_import_one(..., folder=...)`（电脑/手机上传统选择了文件夹）
4. 待确认列表「确认导入」时带文件夹
5. 程序启动时 `enqueue_existing()` 补旧图

照片移出所有文件夹：不删缓存（无害），后台处理时发现不在文件夹里会跳过。

## 8. 启动

`app/launch.py` 里设置：

```python
os.environ["JLTX_BG_DETECT"] = "1"
```

- 正常双击 `启动.bat` / 开机自启都走 `app.launch` → 后台线程会启动。
- 测试用 `TestClient(main.app)` 不设这个变量 → 后台线程不启动，测试可控。
- 直接 `uvicorn app.main:app` 不设 → 只少了后台预识别，功能不受影响。

## 9. 接口版本

`API_VERSION` 22 → **23**。
没有新增 HTTP 接口，但用户能明显看到"打开文件夹里的图变快了"；而且老进程没有
后台线程，不 +1 的话 `启动.bat` 会以为"工具已经在跑了"，用户永远等不到加速。

## 10. 测试

- DB：`rough_circle` 列迁移；`set_image_rough_circle()` 写入。
- `circle_from_image()`：有候选用候选；没候选给居中圆。
- `cached_or_detect()`：第一次调用检测一次并写缓存；第二次不再调用检测。
- `_process()`：文件夹里的图会写缓存；不在文件夹 / 已标定 / 已有缓存的图跳过。
- `missing_ids()`：只挑「在文件夹里 + 没缓存 + 没标定」的。
- API：带缓存打开时检测函数**一次都不被调用**，圆等于缓存值。
- API：不带缓存打开时会写 `rough_circle`。
- 触发点：单张归档、批量归档、带文件夹导入，都会调用 `enqueue`。
- 全量 pytest + 页面语法/几何检查。

## 11. 决策记录

- 2026-10-22：后台一次一张，静默跑；不改检测算法。
