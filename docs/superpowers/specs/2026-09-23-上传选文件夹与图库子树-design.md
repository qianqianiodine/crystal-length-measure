# 手机上传选文件夹 + 孔位标签；图库按子树看照片

> 2026-09-23 用户提出的四条需求，一次做完。本文件是设计定案，实施计划另见
> `docs/superpowers/plans/2026-09-23-*.md`。

## 背景

照片现在能进库了（拖拽 / 粘贴 / 手机扫码），但**进来的照片没有"位置"信息**：

1. 手机上传时只能起名字，不能选文件夹 —— 照片一律进「未分类」，回头要在电脑上
   一张张归档。
2. 手机上传时不能打孔位标签 —— 必须在电脑上图库里再走一遍「标签…」对话框。
3. 图库里点一个父文件夹是**空的** —— 因为它只显示"直接放在它里面的"，照片都在
   子文件夹里。
4. 测量页的照片下拉框只写名字，看不出这张照片属于哪个文件夹、是哪个孔。

## 目标

| # | 目标 | 验收方式 |
|---|---|---|
| ① | 手机上传时能选文件夹 | 手机上传页有一个文件夹下拉，改完确认导入，照片在图库里就在那个文件夹里 |
| ② | 手机上传时能填孔位，**孔位直接当名字** | 填 `A1-1` → 照片名字 `A1-1`、标签 `A1-1`，图库「标签…」对话框显示得出来 |
| ③ | 单张拍照和批量上传走**同一条路** | 单张传完也进待确认列表，一样能选文件夹、填孔位 |
| ④ | 图库点大文件夹能看到子文件夹里的照片 | 点「样品A」能看到「样品A/6月批次」里的照片 |
| ⑤ | 测量页下拉框显示「小文件夹-孔位」 | 下拉框里写 `部分2-A1-1（已量 3 条）` |

## 不在这一轮

- 一张照片多标签（现在一轮只写一个标签，`images.tags` 是数组但只放一个 —— 不改库）
- 导出图片的命名规则（**已经符合要求**：`exporter.export_plan` 的文件名前缀用的是
  直接父文件夹的名字，`样品A/6月批次/A1-1` → `样品A/6月批次/6月批次_A1-1.png`。
  见 `tests/test_exporter.py::test_导出计划_文件夹名做前缀`）
- 手机上传页显示已有照片（安全模型：手机端只有"传"这一个动作）

## 一、手机上传页

### 页面结构

```
传照片到电脑
[    拍照 / 选照片    ]           ← 不变

这批照片放到                        ← 新增：改它 = 下面所有行都改成它
[ 样品1 / 部分2      ▾ ]

统一前缀 [ EXP0615_ ]              ← 不变

待确认导入（2 张）
┌───┬──────────────┬──┐
│图 │ A1-1         │✕ │
│   │ [部分2      ▾]│  │         ← 新增：每行第二行，改这一行
├───┼──────────────┼──┤
│图 │ A2-1         │✕ │
│   │ [部分2      ▾]│  │
└───┴──────────────┴──┘
[ 确认导入 ]  [ 取消 ]              ← 不变
```

两个下拉的语义：

- **顶部那个 = 批量**：改它，当前列表**每一行**都变成它。手机上 20 张要一起改时用。
- **每行那个 = 单行**：只改这一行。传了 3 张放 A、又传 2 张想放 B 时用。

两个都有是故意的：只留顶部的话，改一次会把前面已经放好的行一起改掉（用户看不出来）；
只留每行的话，20 张要改 20 次。

### 单张也走待确认列表

`web` 侧的 `mobile.py` 里，手机页现在按 `files.length >= 2` 决定 `mode=pending|direct`。
**改成恒为 `pending`**。这样单张拍完也停在列表里，能选文件夹、能填孔位。

⚠️ 电脑端**不动**：电脑端一个请求带多个文件，`mode=auto` 的老规则继续用。

### 文件夹树从哪来

`_pending_list()` 的返回值里加 `folders`（和 `GET /api/folders` 的 `items` 同形状：
`id / name / parent_id / depth`）。手机页靠 `depth` 画缩进。

⚠️ 这是手机页第一次显示库里的**内容**（之前只有"传"）。只暴露文件夹**名字**，
不暴露任何照片。安全上可接受，但要写进风险清单（见第九节）。

## 二、孔位标签 = 名字

手机上**只有一个输入框**，它同时是名字和标签：

```
s = 输入框内容.strip()
if s 空:
    名字 = 原始文件名（去掉扩展名），标签 = 空        ← 和现在一样
elif _TAG_RE.fullmatch(s.upper()):
    名字 = 前缀 + s.upper()，标签 = [s.upper()]
else:
    名字 = 前缀 + s，标签 = 空
```

`_TAG_RE` **复用 `app/api/images.py` 里那一个**（`^[A-H]([1-9]|1[0-2])-[12]$`），
不要在这里写第二份 —— 两份迟早分叉。

⚠️ 为什么"不像孔位就不存标签"：图库的「标签…」对话框靠 `A1-1` 这个形状把标签
拆回三个下拉（`web/gallery.html` 的 `TAG_ROWS/TAG_COLS/TAG_HOLES`）。存进去一个
`IMG_1234`，那个对话框就显示不出来了。所以不是孔位就只当名字。

⚠️ 为什么 `.upper()`：用户在手机上打小写 `a1-1` 很正常。转成大写后名字和标签一致，
图库那边的下拉才认。

## 三、默认文件夹从哪来（用户选 b）

**默认 = 你在图库点「手机传图」那一刻正看的文件夹。**

实现走 QR URL 的查询串，不动数据库：

- `GET /api/net/qrcode?i=0&folder=<id>` → `_urls()` 拼出 `http://<ip>:<port>/m/<令牌>?folder=<id>`
- `GET /api/net/info?folder=<id>` → 返回的 `urls` 同样带 `?folder=`
  （二维码旁边那段文字 URL 要跟二维码一致）
- `web/gallery.html` 打开手机传图弹窗时，把 `S.folder` 传上去

手机页：

- 从 `location.search` 读 `folder`，作为**上传时的默认文件夹**
- 上传请求：`POST /m/<令牌>/upload?mode=pending&folder=<id>`
- 新暂存的每一行 `folder_id` 就取这个值

⚠️ 中间件 `main.py` 的 `lan_guard` 比的是 `request.url.path`，查询串不参与
（已有的 `?x=/m/<T>` 绕过尝试实测就是被拦掉的）—— 加 `?folder=` 不影响安全模型。

用户在图库看的是「全部照片」（`S.folder === ''`）或「未分类」（`'0'`）时：
**不传 `folder` 参数**，照片默认进「未分类」。和现在的行为一致。

⚠️ 那个文件夹在扫码之后、上传之前被删了：服务端 `db.get_folder()` 查不到就当
「不放进文件夹」，不报错。

### 电脑端拖拽上传也一样

`web/gallery.html` 的拖拽/粘贴上传也带 `folder=<当前图库看的文件夹>`。
不这么做的话，同一批照片从手机传和从电脑拖会落到不同地方。

## 五、图库：点大文件夹看子树

### 服务端

`app/db.py` 的 `_filter()` 现在把 `folder` 编译成 `f.folder_id = ?`（只看直接的）。
改成**子树**：

```python
def _filter(conn, status, q, folder=None):
    ...
    if folder is not None:
        if folder == 0:
            conds.append("NOT EXISTS (SELECT 1 FROM image_folders f WHERE f.image_id=images.id)")
        else:
            subs = subtree_ids(conn, folder)
            marks = ",".join("?" * len(subs))
            # ⚠️ 必须写成 `images.id IN (子查询)`，不能写
            # `EXISTS (... AND f.folder_id IN (...))`：后者在 SQLite 3.51.0 上
            # 会按子查询的匹配行数吐重复的外层行（一张照片同时在父子文件夹里
            # → 图库里出现两张一样的卡片）。实测 `IN (1)` 不犯、`IN (1,2)` 就犯，
            # ANALYZE 之后又正常 —— 计划器的坑，别赌。见 learnings.md。
            conds.append(f"images.id IN (SELECT f.image_id FROM image_folders f"
                         f" WHERE f.folder_id IN ({marks}))")
            params.extend(subs)
```

调用方（都在 `db.py` 里，都有 `conn`）：`list_images` / `count_images` / `ids_matching`
三个都改成传 `conn`。

⚠️ `subtree_ids()` 已经存在（`db.py:429`），它用 `UNION` 而不是 `UNION ALL` 防数据出环 ——
**直接复用，别新写一个递归 SQL**。

### 张数（必须一起改，否则自相矛盾）

`db.folder_counts()` 现在是"每个文件夹**直接**装了几张"。改成**连子文件夹**：

```python
def folder_counts(conn) -> dict[int, int]:
    """每个文件夹**连同子文件夹**一共装了几张。同一张照片只算一次。"""
    out = {}
    for row in conn.execute("SELECT id FROM folders"):
        subs = subtree_ids(conn, row["id"])
        marks = ",".join("?" * len(subs))
        out[row["id"]] = int(conn.execute(
            f"SELECT COUNT(DISTINCT image_id) c FROM image_folders"
            f" WHERE folder_id IN ({marks})", subs).fetchone()["c"])
    return out
```

⚠️ `COUNT(DISTINCT image_id)` 是必需的：一张照片可以同时被放进父和子（多对多），
不去重就会重复计数，出现"点进去只有 3 张、树上写 6 张"。

⚠️ 性能：文件夹有 N 个就查 2N 次。N 是几十，SQLite 本地，可以接受。
**不要**为此提前做整套记忆化 —— 等它真的慢了再说（Karpathy：简单优先）。

### 连带影响（必须让用户知道）

1. **「选中全部 N 张」的数字会变大** —— `ids_matching()` 也走 `_filter()`，
   所以点大文件夹再全选，选中的是**整棵子树**的照片。之后的批量删除/移动/导出
   作用面跟着变大。
2. `folder_delete_plan()` **不受影响** —— 它自己算子树，不用 `folder_counts()`。
3. 「未分类」（`folder=0`）语义**不变**：不属于任何文件夹的照片。

## 六、测量页下拉框

`web/measure.html` 的 `loadPhotos()` 里那个 `o.textContent`。

现在：

```js
o.textContent = it.line_count ? `${it.name}（已量 ${it.line_count} 条）` : it.name;
```

改成：

```js
const fn = it.folders.length ? folderName(it.folders[0]) : '';   // 叶子名
const tg = it.tags.length ? it.tags[0] : '';
const head = fn && tg ? `${fn}-${tg}`
           : fn       ? `${fn}-${it.name}`
           : tg       ? tg
           :            it.name;
o.textContent = it.line_count ? `${head}（已量 ${it.line_count} 条）` : head;
```

| 情况 | 显示 |
|---|---|
| 有文件夹有标签 | `部分2-A1-1` |
| 只有文件夹 | `部分2-IMG_1234` |
| 只有标签 | `A1-1` |
| 都没有 | 照片名字（和现在一样） |

⚠️ **只写小（叶子）文件夹名，不写整条路径** —— 用户明确要求名字别太长，而且
和导出的命名规则保持一致（导出也是只用直接父文件夹做前缀）。

⚠️ 代价：两处都有「部分2」这种同名小文件夹时，下拉框里分不清。用户已知悉并
选择短名字。真被咬到再改成"重名时补父级"。

⚠️ `it.folders` 可能有多项（多对多）。**只显示第一个**（按 `folder_id` 升序，
服务端 `db.image_folders()` 已经排好序）。全列出来下拉框会撑爆。

⚠️ `FOLDER_NAMES` 由 `loadFolderNames()`（`measure.html:1924`）异步加载，
只有叶子名。`loadPhotos()` 必须在它之后跑 —— 现有的 `scopeName()` 已经有这个
依赖了，新代码沿用，不额外加等待逻辑。

## 九、风险（动手前已告知用户）

1. **手机页会显示文件夹名字**。开口子的 30 分钟里，拿到令牌的人能看到文件夹树
   （只是名字，不是照片）。这是手机页第一次暴露库里的内容。
2. **图库每个文件夹右边的数字会变大**（改成子树计数）。用户可能觉得"怎么变多了"。
3. **「选中全部」的作用面变大**。点大文件夹再全选，现在选中整棵子树的照片，
   后续的批量删除/移动/导出都跟着变大。**这条最要紧**。
4. **测量页下拉框可能同名分不清**（只写叶子文件夹名）。
5. **单张上传多一次点击**（要停下来点「确认导入」）。
6. **孔位格式写错不会报错** —— 只是不存标签，名字照样用你写的。在图库点
   「标签…」才会发现是空的。
